= conductor

A self-hosted task tracking app for small teams.

Built with Go, templ, HTMX, AlpineJS, SQLite, and Tailwind CSS. Ships as a static binary or a single Docker container.

== Prerequisites

* https://go.dev/dl/[Go 1.26+]
* https://templ.guide/quick-start/installation[templ CLI]: `go install github.com/a-h/templ/cmd/templ@latest`
* https://tailwindcss.com/blog/standalone-cli[Tailwind CSS standalone CLI]: `brew install tailwindcss`

NOTE: templ and Tailwind are dev-only dependencies. The Docker build handles them inside the container.

== Local development

[source,shell]
----
make run
----

This generates templates and CSS, then starts the server at http://localhost:8080. The database is created at `./conductor.db` automatically.

You will need to create an admin user before you can log in:

[source,shell]
----
CONDUCTOR_DB_PATH=./conductor.db go run ./cmd/conductor admin add-user <username> <password>
----

Other useful targets:

[source,shell]
----
make help       # show all available commands
make lint       # format and vet all source files
make test       # run lint then all tests
make generate   # re-run templ code generation and recompile Tailwind CSS
make seed       # seed local database with test users, projects, and tasks
make clean      # remove generated files and local database
----

== Admin CLI

The `conductor admin` subcommand manages users directly against the database. Run it on the same machine as the database, or inside the container via `docker compose exec`.

On a native install the database path is read automatically from `/etc/default/conductor`:

[source,shell]
----
sudo conductor admin list-users
----

Pass `--help` to any command for a usage reminder:

[source,shell]
----
conductor admin --help
conductor admin add-user --help
----

=== List users

[source,shell]
----
conductor admin list-users
----

=== Add a user

[source,shell]
----
conductor admin add-user <username> <password>
----

[source,shell]
----
$ conductor admin add-user alice password
created user "alice" (id=1)
----

=== Delete a user

[source,shell]
----
conductor admin delete-user <username>
----

[source,shell]
----
$ conductor admin delete-user alice
deleted user "alice"
----

=== Reset a password

[source,shell]
----
conductor admin reset-password <username> <new-password>
----

[source,shell]
----
$ conductor admin reset-password alice newpassword
password reset for user "alice"
----

=== Running admin commands inside Docker

[source,shell]
----
docker compose -f deployments/docker/docker-compose.yml exec conductor /conductor admin list-users
docker compose -f deployments/docker/docker-compose.yml exec conductor /conductor admin add-user alice password
docker compose -f deployments/docker/docker-compose.yml exec conductor /conductor admin delete-user alice
docker compose -f deployments/docker/docker-compose.yml exec conductor /conductor admin reset-password alice newpassword
----

== Deployment

Compose and native deployment files live under `deployments/`.

=== Docker Compose

==== Plain HTTP (port 8080)

[source,shell]
----
docker compose -f deployments/docker/docker-compose.yml up -d
----

The app listens on port 8080. The SQLite database is stored in the `conductor_data` Docker volume.

[source,shell]
----
docker compose -f deployments/docker/docker-compose.yml down       # stop
docker compose -f deployments/docker/docker-compose.yml logs -f    # follow logs
docker compose -f deployments/docker/docker-compose.yml restart    # restart
----

NOTE: The default compose file sets `CONDUCTOR_SECURE_COOKIE=false`. Set it to `true` when running behind HTTPS.

==== HTTPS via Caddy

For internet-facing deployments with automatic TLS via Let's Encrypt:

[source,shell]
----
DOMAIN=tasks.example.com docker compose -f deployments/docker/caddy/docker-compose.yml up -d
----

Caddy handles ports 80 and 443. Conductor is not exposed to the host directly — Caddy reaches it over the internal Docker network. Certificates are provisioned and renewed automatically.

=== Pre-built image (GHCR)

Each release tag publishes a multi-arch Docker image (`linux/amd64`, `linux/arm64`) to the GitHub Container Registry. Tags produced: `latest`, `vX.Y.Z`, and `vX.Y`.

To use the pre-built image instead of building locally, update `deployments/docker/docker-compose.yml`:

[source,yaml]
----
services:
  conductor:
    image: ghcr.io/agiannif/conductor:latest
    # remove the "build: ." line
----

=== Native (Linux, no Docker)

Installs a static binary and a systemd service. The installer asks one question and configures everything accordingly.

[source,shell]
----
curl -fsSL https://raw.githubusercontent.com/agiannif/conductor/main/deployments/native/install.sh | sudo bash
----

The installer presents three access modes:

[source]
----
How should users access conductor?

  1) http://hostname:8080   — simple, no extra config  [default]
  2) http://hostname        — port 80, no port needed in the URL
  3) https://yourdomain.com — HTTPS via Caddy (requires a public domain)
----

* **Mode 1** — default, no extra dependencies.
* **Mode 2** — grants the binary `CAP_NET_BIND_SERVICE` so it can bind port 80 without running as root.
* **Mode 3** — installs Caddy (Debian/Ubuntu only via apt), writes a Caddyfile, and obtains a TLS certificate from Let's Encrypt automatically. Requires a public domain pointing at the server.

To pin a specific version, pass `VERSION` before the pipe:

[source,shell]
----
curl -fsSL https://raw.githubusercontent.com/agiannif/conductor/main/deployments/native/install.sh | sudo VERSION=v1.0.0 bash
----

To skip the prompt and install in HTTPS mode non-interactively, pass `DOMAIN`:

[source,shell]
----
curl -fsSL https://raw.githubusercontent.com/agiannif/conductor/main/deployments/native/install.sh | sudo DOMAIN=tasks.example.com bash
----

The installer detects your CPU architecture automatically (`amd64`, `arm64`, `armhf`).

After install:

[source,shell]
----
systemctl status conductor        # check service status
journalctl -u conductor -f        # follow logs
sudo conductor admin add-user <username> <password>  # create first user
----

==== Uninstall

[source,shell]
----
curl -fsSL https://raw.githubusercontent.com/agiannif/conductor/main/deployments/native/uninstall.sh | sudo bash
----

WARNING: The uninstaller removes everything — binary, service, configuration, and the database. All task data will be lost.

== Configuration

Configuration is via environment variables. On a native install these are set in `/etc/default/conductor` by the installer.

[cols="2,1,3"]
|===
| Variable | Default | Description

| `CONDUCTOR_DB_PATH`
| `/data/conductor.db`
| Path to the SQLite database file.

| `CONDUCTOR_SECURE_COOKIE`
| `true`
| Set the `Secure` flag on session cookies. Set to `false` for local HTTP development or when not behind HTTPS.

| `CONDUCTOR_LISTEN_ADDR`
| `:8080`
| Address and port the server binds to. Set to `:80` for direct port 80 access, or `127.0.0.1:8080` when running behind a reverse proxy.
|===

== Building

=== Local binary

[source,shell]
----
make build
----

Generates templates and CSS, then compiles the `conductor` binary in the project root.

=== Docker image

[source,shell]
----
make image
----

Generates templates and CSS, then builds a Docker image tagged `conductor`.

CI builds and pushes the image to GHCR automatically on each release tag. See the <<Pre-built image (GHCR)>> section for using the published image.
